# XDB v2 设计说明

> 目标：在 v1（B 链接树 + 页内版本链 + 旁路映射 + 崩溃自愈）的基础上，把
> **写放大** 和 **页内布局的稳定性** 做成硬约束，并把「回滚/恢复」从原地修补
> 改为可验证的整树重建。

---

## 1. 与 v1 的关键差异

| 维度 | v1 | v2 |
| ---- | -- | -- |
| 页内布局 | 槽区/值区共享增长，部分更新需搬移 | **定位式原子布局**：元数据在固定偏移，槽区只追加，值区向下生长 |
| 元数据更新 | 读-改-写多字节 | 单次 4B 对齐写（word） |
| 提交点 | map 页写 | map 页 `state` 单 4B 写（0xA55A），A/B 轮换 |
| 回退 | 逐页 settle 修补 | **整树重建**（`rebuild_from`）+ 精确空闲表重建 |
| 页回收 | 近似（可能双重释放/丢失） | 以可达性为准：`refresh_free()` 重建 `used_`/空闲表 |
| 调试 | 零散打印 | 宏开关：`XDB_ASSERT_SORTED` / `XDB_ALLOC_TRACE` / `XDB_ORPHAN_TRACE` / `XDB_RB_TRACE` / `XDB_CORRUPT_TRACE` / `XDB_COMMIT_CHECK` |

## 2. 页布局（4B 对齐的「定位式原子」）

```
0        16        32                       ...                  PAGE-384     PAGE
+--------+---------+--------------------------+---------------------+----------+
| PageHdr| LeafHdr |  槽区（只追加，4B 单元）  | 空闲 |  值区（向下生长） |  导航带  |
+--------+---------+--------------------------+---------------------+----------+
                    ^                                   ^
             LEAF_DATA0 → +                 SLOT_CUR0 ← 值头/值向下占用
```

* **槽区只追加**：每写入一条 PUB 槽（20B = 5 个 4B 单元），`nslots` 才 +1；
  旧 4B 字永不改写 ⇒ 无移位、无读-改-写放大。
* **值区向下**：值头 `VALHDR{kind,chk,flags,len}` 紧贴值数据；分配只改
  `data_off`（4B 写）。
* **页自校验**：每槽首字节为 `kind`，第二字节为 `chk = f(kind, 字段)`，
  读到不完整槽（掉电）即停止扫描 ⇒ 页内天然「前缀一致」。
* **Foot**：页自身的小 redo 记录 `{vers, nslots, data_off, rolls[64], min_key}`，
  恢复时据此截断；`Foot` 之后才是页 CRC/哈希。**写顺序**：值 → 值头 → 槽 →
  头/尾/哈希 → 脏字刷出 → 映射页。

> 关键教训：任何「先写页头/初始化页，再判断容量」的路径都是错的 ——
> 失败返回会在缓存里留下空白页，提交时被当作正常页关闭，形成孤儿页。
> 容量判断必须在第一次写之前完成（见 `build_leaf`）。

## 3. 并发可见性与 MVCC

* 版本号 `ver` 单调递增；**可见性 = `ver ≤ view`**（`open_` 为当前事务视图）。
* 未提交批的 `ver = open_ = vers_ + 1`，读不到；`abort()` 依据 Foot 回退。
* `gather_view(page, view, drop_tombs, keep_from)`：
  * 每键**只保留 ≤ view 的最新版本**，以及 `ver ≥ keep_from` 的旧版本（快照/历史窗口）；
  * 最新版本是墓碑（`r_off = 0`）⇒ 该键整体不可见（`drop_tombs` 时直接丢弃）；
  * 输出按 `key` 升序、`ver` 升序。
* `history_floor()`：有快照时返回 0（必须保留全部历史），否则 `open_ - HORIZON`。

## 4. 分裂与分隔键

* **叶分裂**：切点必须落在**键边界**上（同一键的所有版本同页）。若整页只有一个键
  （无法切分），退化为 `settle(pid, newest_only=true)`（只保留最新版本重写）。
* **内页分裂**：槽是「子页键下界」，因此**不做中间槽提升**，直接把槽数组对半分：
  `L = s[0..mid-1]`、`R = s[mid..n-1]`，向祖父层插入 `(s[mid].key → R)`。
  > 曾经尝试「提升中间槽」，导致该槽引用的子树在父页中消失（孤儿叶），
  > 且在根分裂时子树彻底丢失。
* **分隔键只降不升**：`lower_sep` 只把键改小，并向左传播保持单调；路由用
  「最大 ≤ target 的槽」，下界语义与只降一致。
* 叶子 `min_key` 只减不增（`min_hint` 保住空页的原下界）。

## 5. 事务、提交与恢复

```
put/del ─→ leaf_insert（追加槽+值）─→ 满则 relief：settle（压缩重写）或 split
commit ─→ close_page（写 Foot + 页哈希）─→ flush_all ─→ write_map(open_+1)
```

* **提交点**：映射页 `state` 4B 写 `0xA55A`，A/B 两页轮换；挂载取「校验通过且
  `next_vers` 最大」的那一份。
* **挂载**：读 map → 校验根 → 扫描全部页重建 `used_`/空闲栈/`max_fv` →
  截断到 Foot（丢弃未提交批）。
* **`abort()`**：`root_ = root_c_`（上次提交的根），按 Foot 截断已开页，
  释放本事务分配页，然后 **`refresh_free()`** 依可达性精确重建空闲表。
* **`rollback(snap)`**：`abort()` → 以快照保存的**叶页集合** + 版本屏障重建整棵树
  （`rebuild_from`）→ `refresh_free()` → 写 map。
  * 为什么用快照的叶集合而不是当前叶链：回退后当前链可能已被推进过，
    而快照页被 pin 住、内容只追加，按屏障取值即快照时刻的精确内容。
  * `rebuild_emit` 的切页条件按**键组**判断（组内所有版本必须同页）。

## 6. 页缓存与不可换出约束

* 导航缓存 `NAV_CAP`（默认 64，可用 `-DXDB_NAV_CAP=N` 增大）。
* **绝不跨 `load()` 持有 `Entry*`**：`load()` 可能换出任意页（包括自己）。
  典型事故：`new_root` 先 `make(nr)` 写头，随后 `load(left/right)` 把 `nr` 换出，
  再写 `e->b` 就把内容写进了别的页，`nr` 落盘为空白内页。
* 换出优先已提交页；未提交页（`open`）只在必要时换出——它们落盘后由 Foot
  保证可回退。
* 提交时按 `oset_` 过滤 `olist_`：**本事务内已回收的页不再参与收尾**，
  否则空页会被当成正常页关闭。

---

## 7. 空闲表与可达性

* 唯一可信来源是**可达性**：`refresh_free()` 从 `root_` 走 BFS 标 `used_`，
  其余非 pin 页进入空闲栈；同时丢弃缓存中「已不再有效」的页，避免脏数据写回。
* `release_page(pid, tag)` 幂等（`if (!used_[pid]) return;`），并清 `oset_`。
* 分配时跳过 `used_` 为真的陈旧空闲条目（双保险）。

## 8. 测试矩阵

| 测试 | 内容 | 结果 |
| ---- | ---- | ---- |
| t1 | 基础读写/覆盖/删除 | OK |
| t2 | 随机 400 ops × 6 轮 × 5 种子，含事务/重开 | FAILURES: 0，孤儿 0 |
| t3 | 20000 ops 规模（深树/多内页）+ 快照 + 回退 + abort + 断电重开 | FAILURES: 0 |
| t4 | 只插入（无删除）规模 | OK |
| t5 | 边界（空页/单键页/大值） | OK |
| t6 | 大量删除（4600 ops，10% del） | `scan == oracle` |
| tchk | 树 vs 叶链 vs 全量扫描一致性 | missing=0 extra=0 |
| x1 | 5 轮提交后逐键回读（语义） | PASS |
| x2 | **每个写操作后**检查「树可达叶集合 == 叶链集合」并检测泄漏 | PASS |

`make dbg`（`XDB_ASSERT_SORTED` + `XDB_SETTLE_CHECK` + `XDB_CORRUPT_TRACE`）
与 `-DXDB_COMMIT_CHECK`（每次提交后全量校验）在 t2/t3/t6 上均通过。

调试开关：

```
-DXDB_ASSERT_SORTED   内页槽序/重复子页断言
-DXDB_SETTLE_CHECK    settle/split 前后条目数一致
-DXDB_KTRACE=<key>    指定键的构建追踪
-DXDB_ALLOC_TRACE     页分配/回收日志 + 空页关闭点栈
-DXDB_ORPHAN_TRACE    verify 时列出孤儿页及最近构建历史
-DXDB_RB_TRACE        回退重建后自检（链/键序/降级路径）
-DXDB_CORRUPT_TRACE   CORRUPT 返回点定位
-DXDB_COMMIT_CHECK    每次提交后全量校验（极慢）
```

## 9. 基准（`bench/bench_v1.cpp` 与 `bench/bench2.cpp`，同一负载）

负载：20000 次 `put`（键 1..200000 随机，值 4–28B），每 500 次提交一次。

| 引擎 | 逻辑值字节 | 设备写字节 | 写放大 | 设备读字节 | 读调用 | 用时 |
| ---- | ---------: | ---------: | -----: | ---------: | -----: | ---: |
| v1 | 310,440 | 17,437,360 | 56.2× | 90,363,664 | 352,984 | 0.244s |
| v2（NAV_CAP=64） | 310,440 | 6,987,380 | **22.5×** | 317,014,016 | 77,396 | 0.084s |
| v2（NAV_CAP=512） | 310,440 | 5,933,228 | **19.1×** | 8,192 | 2 | 0.070s |

读放大完全由导航缓存容量决定：把 `NAV_CAP` 提到 512 后，整个基准只发生 2 次设备读。
写字节仍高于理论值（~0.4MB），主要来自：COW 整页重写（分裂/settle）、
页尾 Foot+哈希、以及每 500 ops 一次 map 页。

50000 ops / 每 1000 提交（v2）：写 16.35MB（NAV_CAP=512），0.224s，744 叶、5 内页。

## 10. 未完成/后续

* 页缓存替换策略仍是朴素 LRU 扫描（O(cap)），可换时钟/分段 LRU。
* settle 的收益判断用估算（`need + 256 < data_off + 4096`），可改为精确收益。
* 内页无「兄弟借位」，只有分裂；删除后不做合并（v1 亦如此）。
* `-DXDB_COMMIT_CHECK` 只能小规模使用（O(n²) 感）。
